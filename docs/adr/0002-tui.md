# 0002. TUI views and interaction

Status: Accepted (2026-11-27)

## Context

These records hold the non-obvious reasons behind the code in this area. They were collected
from the source comments removed under [ADR 0001](0001-no-code-comments.md). Each section is
one decision. When code here changes, update or retire the section that covers it.

## Decisions

### Hub-mode Processes polling

**Context:** The Processes view in hub mode polls the hub for one device's process list.

**Decision:** The hub keeps the device's agent sending its process list only while polls continue, so the TUI runs exactly one poll loop (a generation counter is bumped each time the view opens), tags results with the device they belong to and drops answers for another device, and stops polling when the viewer leaves so the hub's watch runs out.

**Consequences:** Removing the generation or device check would show one device's processes under another's name or leave the agent sending data nobody reads.

**Where:** `internal/tui/actions.go`

### Power actions

**Context:** Sleep/restart/shutdown go through a confirmation prompt.

**Decision:** Device state is re-checked when the user confirms, because the device may have gone offline or turned power actions off while the prompt was open.

**Consequences:** Skipping the re-check would send an action the agent no longer permits.

**Where:** `internal/tui/actions.go`

### Add device and upstream hub compat

**Context:** Add device shows a pairing code and one-line installs for our hub and for the upstream Electron hub (server.js).

**Decision:** The hub is detected as upstream by its open /api/info lacking impl "machine-monitor" (a hub that cannot answer counts as ours). Upstream differs: its code allows 5 tries total instead of 5 per device, and its install.sh starts with #!/usr/bin/env bash, so the bash installer line is used for it. When reached over a loopback port forward, the hub's own listening port is advertised to other machines. The install lines hide the key until asked, for screen sharing, and a dropped stream means the code is gone because it lived only in that hub's memory.

**Consequences:** Treating every hub as ours would print wrong limits and the wrong installer; always showing the key leaks it on shared screens.

**Where:** `internal/tui/add.go`

### Alerts view state

**Context:** The Alerts view state lives in the model, which Bubble Tea copies on every Update.

**Decision:** Slices are cloned before they change. Saves and fetches are numbered: a fetch that began before a save and lands after it is stale and dropped, so it cannot put old rules back. The hub's tempUnit should follow the Settings unit once alerts load.

**Consequences:** Editing shared slices in place leaks into old model copies; accepting stale fetches loses saved rules.

**Where:** `internal/tui/alerts.go`

### Alerts delete confirmation

**Context:** Deleting a rule asks y/n.

**Decision:** The question remembers the rule by id. It is cancelled if that rule is gone or moved, but not when its fields change or when an echo of the user's own earlier save arrives late, since the delete still hits the same rule.

**Consequences:** Cancelling on every settings event made the confirmation flaky; not cancelling on a moved rule would delete a neighbour.

**Where:** `internal/tui/alerts.go`

### Alerts rule editor

**Context:** The rule/channels editor edits a copy of the hub's settings.

**Decision:** The editor follows its rule by id to a new position, or closes if it is gone, so saving cannot overwrite another rule; the cursor is clamped so saves never index past the list. New rules take the type's default threshold and minutes, an edited one keeps its own (offline needs >=1). Daily-cost rules hide minutes (checked once per day). Channels switched on without an address are caught locally because the hub would silently switch them off. Rule types are listed in upstream's dashboard order, and the text cursor does not blink so the form needs no ticks.

**Consequences:** Changing these would let a save overwrite the wrong rule or silently lose a channel.

**Where:** `internal/tui/alerts.go`

### Hub error text

**Context:** Errors shown in the footer are turned into plain sentences.

**Decision:** Windows reports connection refused as WSAECONNREFUSED, which is not syscall.ECONNREFUSED there, so it is matched separately. Hub messages are shown as is, usual network failures get plain words, never Go's raw Get "url": dial tcp text, and leftovers are stripped of control characters.

**Consequences:** Dropping the Windows constant makes refused connections show a raw error on Windows.

**Where:** `internal/tui/alerts.go`

### Alerts temperature units

**Context:** The hub stores alert temperature thresholds in °C.

**Decision:** The TUI shows and accepts the user's unit and converts at the edges, to one decimal at most.

**Consequences:** Storing °F would break the hub's rules.

**Where:** `internal/tui/alerts.go`

### Alerts regression tests

**Context:** Regression tests for races between fetches, saves and settings events.

**Decision:** Tests assert: selection follows an accepted new rule rather than the old list; the editor closes when its rule is removed; a delete question is withdrawn when the rule under the cursor changed; the echo of our own save does not cancel a delete (this raced a flaky test); a stale fetch must not restore old rules.

**Consequences:** Consequences: these tests guard the by-id behaviour above.

**Where:** `internal/tui/alerts_test.go`

### History chart rendering

**Context:** Charts render braille (ntcharts) or ASCII lines for the History view.

**Decision:** Styles are rendered once and runs wrapped in the escape sequences because lipgloss rendering is slow; the wrapper assumes escape sequences never contain the placeholder rune X. Series are drawn last first so the first series owns shared cells. Many points can share a dot column, so each column keeps the span of dots covered and lines are traced only between different columns, giving the same result as joining every point. niceMax rounds to 1, 2, 2.5 or 5 times a power of ten as upstream's axes.

**Consequences:** Per-point rendering would miss the 16 ms frame budget.

**Where:** `internal/tui/chart.go`

### Dashboard card layout

**Context:** Device cards share width on wide terminals.

**Decision:** The I/O line falls back from columns to packed to unlabelled so the disk-write rate is never the part that is cut off.

**Consequences:** Fixed layouts hid disk writes at 200 columns.

**Where:** `internal/tui/dashboard.go`

### Device list model

**Context:** Devices come from the local collector or from a hub stream.

**Decision:** Order ties break on first-seen time like the hub. Our hub snapshot has no history so sparklines start live and are seeded later (liveFrom, seeded); an upstream hub snapshot already has history. Edits copy the list first because Bubble Tea copies the model each update and a shared backing array would leak edits into old copies; within a batch the copy is made once. When the stream goes silent nothing is shown online.

**Consequences:** Editing in place corrupts old model copies; trusting stale online flags misleads.

**Where:** `internal/tui/devices.go`

### Energy view upstream compat

**Context:** The Energy view follows upstream's Advanced page.

**Decision:** Buckets are whole local hours (24 h) or local midnights, ranges and defaults (7 d) match upstream, watts/kWh/money formats match upstream (rounding half away from zero like Intl), the hub's own estimate wins over a computed one, cost falls back to the guessed flat rate when no price is saved, and today's cost query sends an ascending pair as the hub requires.

**Consequences:** Changing formats or bounds breaks parity with upstream's numbers.

**Where:** `internal/tui/energy.go`

### Stream lag and header regression tests

**Context:** Tests for a lagging stream and header values.

**Decision:** Reports arriving lateAfter late by the hub's own clock mark data late in header/footer until under lateClear; cards keep the hub's online flags (review of #70 showed '0 online · 250 offline' when data was merely late), and a lag wavering below lateAfter never warns. Cost today and alert count must reach the header via the real Init path: Init runs on a model Bubble Tea discards, so a numbered read was dropped as stale (review of #55).

**Consequences:** Guards skeptic report N1.

**Where:** `internal/tui/features_test.go`

### History key debounce

**Context.** History and Energy reads hit the hub (or local store) on every range, zoom, pan or device key. Terminal key repeat fires many times a second.
**Decision.** Those keys only reschedule a read after `fetchDebounce`; a later key replaces the pending fetch. Replies carry a request counter and a reply for an older request is dropped. `fetchDebounce` is a var so tests can shorten it.
**Consequences.** Holding a key sends one request for the last window. Removing the debounce or the counter makes stale replies overwrite newer windows.

**Where:** `history.go`

### History cursor, zoom and window

**Context.** The charts use ntcharts' braille grid and the hub keeps 30 days.
**Decision.** `cursorTime` matches where ntcharts places a point (2w braille dots over the span) so the readout is the bucket under the cursor. `zoomTo` keeps the time under the cursor fixed, and zooming with the cursor on the last column of a window ending now keeps following now. `setWindow` clamps to the 30 days the hub keeps and never past now; a window as wide as the range that reaches now follows now again.
**Consequences.** Changing the dot math or clamps desynchronises the readout from the plotted line or lets the user pan into data that doesn't exist.

**Where:** `history.go`

### History chart gap rule and clipping

**Context.** Upstream does not draw a line across missing data.
**Decision.** Points further apart than max(3 buckets, 10 s) are not joined (matches upstream). `clipPoints` keeps one point beyond each edge so lines reach the plot edges.
**Consequences.** Dropping the extra points leaves gaps at the plot edges; changing the threshold diverges from upstream charts.

**Where:** `history.go`

### History labels

**Context.** Clock-only labels are ambiguous over long windows.
**Decision.** `timeLabel` follows upstream: clock up to 36 h, day and clock up to 8 days, the day beyond. The info line adds day names for windows such as 24 h, which would otherwise read "10:28 – 10:28".
**Consequences.** Simplifying to clock-only labels brings back the ambiguous range display.

**Where:** `history.go`

### Temperature unit in charts, bands and alerts

**Context.** Values from collectors and the hub are always °C; the user may choose °F in Settings.
**Decision.** Temperatures are stored and compared in °C. Only display conversion (axis, tiles, readout, tables) follows the unit. Colour bands stay in °C and follow upstream's dashboard thresholds: normal below 70, warm below 85, hot above. In hub mode toggling the unit also saves it in the hub's alert settings (`tempUnit`) so alert text written by the hub matches; this waits (`unitPending`) until the alert settings have loaded and still differ.
**Consequences.** Converting stored values or bands would break comparisons, band colours and the hub's alert texts.

**Where:** `history.go`, `theme.go`, `settings.go`

### Hub stream liveness and lateness

**Context.** The dashboard must not claim devices are online when the stream is dead or lagging, without flickering.
**Decision.** Only the hub's own events count as proof of life; the client's reconnect attempts keep arriving while it is gone. The hub sends a status event every 3 s, so 10 s of silence (`staleAfter`) marks online flags unknown. Late data is measured as each report's hub `LastSeen` against the local clock relative to the soonest-arriving report since the snapshot, so a clock difference between hub and TUI cancels out; a snapshot resets that reference (it may be another hub or the clock moved). Lateness uses hysteresis (`lateAfter` to enter, `lateClear` to leave) so a link hovering around one bound doesn't flicker.
**Consequences.** Counting reconnects as activity, or comparing hub and local clocks directly, shows wrong online/late state.

**Where:** `hub.go`

### Hub event batching

**Context.** A busy hub sends over a hundred reports a second; one redraw per report made a 250-device hub unusable.
**Decision.** `waitEvent` gathers events for `batchWindow` (capped at `maxBatch`) and `applyBatch` copies and sorts the device list once per batch. A nil channel is never selected in `waitEvent` because it would block a goroutine forever. `batchWindow` is a var for tests.
**Consequences.** Per-event redraws overflow the client's event buffer, trigger reconnects and re-snapshots.

**Where:** `hub.go`

### Hub reorder rollback

**Context.** A reorder is applied locally at once and saved on the hub; the save may fail after the hub has sent its own order.
**Decision.** `orderGen` counts order and snapshot events; a failed move restores the old order only if no such event arrived since. Moves are between neighbours within the same group (grid or offline row) because screen neighbours are not neighbours in the stored order.
**Consequences.** Dropping the counter lets a late failure undo the hub's newer order.

**Where:** `hub.go`, `model.go`

### Hub sparkline seeding

**Context.** This project's hub sends a compact snapshot with no history.
**Decision.** The selected device's sparklines are filled on demand from /api/history, once, ahead of the live samples that arrived meanwhile, one device at a time as selection reaches it. Merged reports carry every sample they stand for so none are lost.
**Consequences.** Without seeding, sparklines start empty after connecting.

**Where:** `hub.go`

### Hub grid drawing cost

**Context.** Hundreds of devices make drawing every card each frame slow.
**Decision.** Only rows scrolled into view are rendered.

**Where:** `hub.go`

### Hub scale regression test

**Context.** Skeptic report H3: the TUI redrew every card for every report, its 256-event buffer overflowed within seconds, and each reconnect fetched another full snapshot.
**Decision.** TestHub250 keeps a real hub with 250 busy devices and asserts one connection, recent reports for every device, bounded heap and batched frames.

**Where:** `hub250_test.go`

### Local mode parity with the hub

**Context.** Local mode reuses the History and Energy views.
**Decision.** `usageOf` and `localSample` mirror the hub's usage totals and history samples (internal/hub energy.go, registry.go); `round1` matches upstream's `+v.toFixed(1)`.
**Consequences.** Diverging gives different numbers locally than through a hub.

**Where:** `local.go`

### Init versus Update state

**Context.** Bubble Tea copies the model by value and throws away the one Init runs on.
**Decision.** Init changes no state; reads that number their requests in the model (cost today, alerts count) start from `startMsg` in Update. Functions that start requests bump state through `m`, so they must be called before returning `m`.
**Consequences.** Moving request numbering into Init loses it and breaks stale-reply protection.

**Where:** `model.go`

### Terminal-escape sanitising

**Context.** Local mode doesn't pass through the hub's Normalize and an upstream hub's cleaning can't be relied on.
**Decision.** Everything drawn from another machine (reports, process lists, alerts, hub errors) goes through `clean` first, before anything reads the hostname or report strings. `cleanAll` edits in place, safe because views are the only readers of stream data.
**Consequences.** A process named with OSC 8/CSI sequences could write escapes to the user's terminal.

**Where:** `sanitize.go`, `model.go`

### Process lister

**Context.** gopsutil without cgo.
**Decision.** CPU is percent of one core since the previous call (like top), so first-seen processes have nil CPU; GPU columns stay nil. Per-process read errors leave a field nil instead of failing. The uid→name map is cached because os/user lookups are slow without cgo.

**Where:** `procs.go`

### Race-detector frame budget
**Decision.** Frame-time tests are skipped under `-race` because instrumentation makes timings meaningless; the plain run enforces the budget.

**Where:** `race_on_test.go`

### Price validation

**Context.** The hub refuses invalid prices.
**Decision.** The TUI checks price limits as `power.ParseSettings` does (upstream's validEnergySettings), rate > 0 and at most the cap per kWh. A typed rate is the user's own (as upstream). An overlapping time-of-use price keeps its flat rate when loading instead of being dropped.

**Where:** `settings.go`

### Session history store

**Context.** `history.Store` persists minutes to disk.
**Decision.** Local mode with no store given uses a temporary directory that is removed when the TUI exits.

**Where:** `tui.go`

### TUI contracts

**Decision:** ProcessLister is called about every Interval from one goroutine at a time, only while Processes is open, so implementations need not be re-entrant. NO_COLOR applies for any non-empty value (no-color.org). On reconnect the notice is cleared so a stale action error does not hide connection state. Local price validation mirrors the hub (rate > 0 and bounded). History gaps: points further apart than max(10 s, 3 buckets) are not joined, so offline stretches show as holes, as upstream.

**Where:** `internal/tui/tui.go`, `internal/tui/hub.go`, `internal/tui/settings.go`, `internal/tui/chart.go`, `internal/tui/views_test.go`

### Terminal escape neutralisation

**Context:** A hostile hub or report can supply strings with OSC 8 links, C1 CSI/OSC, DCS, bells, bidi overrides and zero-width characters.

**Decision:** Every string from a hub or report (process names, hostnames, labels) passes through clean; no view emits any escape beyond the theme's own SGR colours. Local-mode hostname is cleaned too.

**Consequences:** Tests assert no frame leaks; bypassing clean opens terminal injection.

**Where:** `internal/tui/hostile_test.go`, `internal/tui/round2_test.go`
