# 0003. Hub API, registry and security

Status: Accepted (2026-11-27)

## Context

These records hold the non-obvious reasons behind the code in this area. They were collected
from the source comments removed under [ADR 0001](0001-no-code-comments.md). Each section is
one decision. When code here changes, update or retire the section that covers it.

## Decisions

### Upstream API compatibility

**Context.** The hub reimplements upstream device-monitor's server so upstream agents (agent.sh, agent-macos.sh, agent.ps1) and clients work unmodified.
**Decision.** API paths and JSON shapes match upstream. Unknown paths, and known paths with the wrong method, get a JSON 404. The guard runs upstream's checks in upstream's order before any route (Host header, LAN-only peer, same-origin for state-changing methods, then the rate limit on open paths). Every report passes `report.Normalize` before it is stored or streamed. Our additions are strictly additive (the `/api/info` proof fields, `retry`/`triesLeft` in pair replies) so clients need not parse messages and upstream clients ignore them. Tailscale `platform` uses Node's `process.platform` names. A missing memory `used` is 0 % upstream; here it stays nil ("unknown is nil, never 0"). Some quirks are kept deliberately: `Number("")` is 0 in JS, so `?bounds=` parsing treats empty entries as 0; a new device with no history rows from before upstream stored peaks is tolerated.
**Consequences.** "Simplifying" these to idiomatic Go would break upstream agents/clients. Deviations from upstream must stay additive.

**Where:** `hub.go`, `handlers.go`, `energy.go`, `pair.go`, `registry.go`, `remote.go`, `commands.go`

### Remote power actions (signed commands)

**Context.** "sleep", "restart", "shutdown" ride in the plain-HTTP reply to an agent's report, so a LAN MITM could inject one.
**Decision.** Commands are queued per device and delivered in the device's next report reply, only if the agent advertised the action (it runs with `--allow-power-actions`). Each is HMAC-SHA256 signed: `hex(HMAC(key, "machine-monitor-cmd:<device>:<id>:<action>:<t>"))`, t in Unix ms. Upstream signs only `device-monitor-cmd:<id>:<action>`; ours also binds the device id and queue time so a command cannot be copied to another device or replayed after CommandTTL (the agent enforces the TTL too). Enrolled devices sign with a private per-device key, legacy devices with the hub token. The id is 6 random bytes (12 hex chars), which `actionResult.id` must match. One command per action is queued; asking again replaces it (as upstream). The queue is emptied on every reply, so a command is delivered at most once, and only those within CommandTTL whose action the report still allows. The action state has its own lock which is never held while taking `mu`. "wake" is sent by the hub itself as Wake-on-LAN to stored MACs.
**Consequences.** Changing the signed string is a protocol change that breaks deployed agents.

**Where:** `commands.go`, `registry.go`, `commands_test.go`

### Per-device keys and the hub's own report

**Context.** Enrolled devices have their own keys; the hub also reports on itself in-process.
**Decision.** The hub's self-report never crosses the network, so it needs no device key (and carries the hub key implicitly) even when `connect` enrolled this machine's own id on the hub machine; otherwise enrolling would stop the hub monitoring itself.

**Where:** `registry.go`, `device_keys_test.go`

### Report intake ordering and locking

**Context.** Agents may post concurrently; the alerts engine and SSE call back into the hub.
**Decision.** Reports for one device are applied one at a time, in full (per-device ingest lock), so LastSeen, history samples and "report" events stay in time order. Alert engine calls happen outside `mu` because the engine calls back into `alertDevices`, and `alertDevices` must never call into the engine (it may hold its own lock). Processes-on-demand data is kept apart from the report. The biggest GPU is sorted first so the main gauge shows the real GPU, not a small display card.
**Consequences.** Calling the alerts engine under `mu`, or holding the action lock while taking `mu`, risks deadlock.

**Where:** `registry.go`, `commands.go`, `pair.go`, `hub_test.go`

### Processes on demand

**Context.** Process lists are large; agents send them only while someone looks.
**Decision.** Each GET on `/api/devices/:id/processes` extends a watch by ProcsWatch; the report reply carries `procs:true` while the watch lasts. Lists nobody asked for are dropped; stored lists are never mutated so handlers can share them. The hub's own list is cut to the busiest rows (CPU, then memory, unknowns last) before Normalize truncates, so the rows that matter survive.

**Where:** `procs.go`

### Hub key, config.json and data directory lock

**Context.** The hub key is issued once and agents hold it.
**Decision.** A damaged config.json is an error, never silently replaced, since a new key would lock out every agent. Keys written by other versions or tools are preserved in `extra`. An invalid time-of-use price already in the file keeps its flat rate (logged once) instead of wiping the price. A damaged history file loses only that device's history. The data directory is locked with an exclusive flock (Windows: LockFileEx) so a second hub on it is refused rather than interleaving history; the OS releases the lock on crash so none goes stale.

**Where:** `hub.go`, `lock.go`

### Hub lifecycle and shutdown
**Decision.** `Run` ends every SSE stream when it returns so `http.Server.Shutdown` doesn't wait on them; `Close` is called after Run and shutdown. LAN discovery fails soft (the port may be taken); the hub works without it. Tailscale CLI reads are serialised by `remoteReads`, a separate lock from `rmu`, because the guard reads the cached status on every request and must never wait on a CLI.

**Where:** `hub.go`

### Failed-report budget (anti-flood)

**Context.** The key lives in a report's body, so it can only be checked after the body (up to maxBody) is read.
**Decision.** An address with `reportFailMax` failed reports in a RateWindow gets only `reportPeek` bytes read: a report whose key is in them goes on, anything else is refused. Every agent puts "token" near the start. A keyed report does *not* clear the address's count, or anyone behind the same NAT or loopback could send another `reportFailMax` big bodies after each success. An agent left with an old key posts ~30/min and so keeps getting the clearer 401.

**Where:** `handlers.go`, `hub_test.go`

### Open endpoints and rate limiting
**Decision.** Paths that answer without the key are rate-limited per source: RateMax per RateWindow. The source is an IPv4 address or an IPv6 /64 (one machine can take any address in its /64: SLAAC privacy, ULA, link-local; link-local peers share fe80::/64). The same key is used for the failed-report budget and pairing tries. The table is bounded: when full, new clients share the socket's allowance, so rotating forwarded addresses can't grow it.

**Where:** `handlers.go`, `security.go`, `hub_test.go`

### Client address and X-Forwarded-For
**Decision.** The client address is the socket's, unless the socket is a proxy in config.json `trustedProxies`. X-Forwarded-For is read from the right (proxies append the address they saw), skipping trusted proxies; the first other entry is the client; anything to its left is client-typed. At most `maxForwardHops` entries are read (real chains are 1-2; a client can send thousands); an unparsable rightmost entry falls back to the socket. A loopback socket is never believed even when listed: every local program connects from loopback, so trusting it would let any local user forge sources (burn another device's pairing tries, fill the rate table). Upstream honours XFF from every loopback peer; we deliberately don't.

**Where:** `security.go`, `hub_test.go`, `install.go`

### Host check, LAN-only peers, CSRF, headers
**Decision.** DNS-rebinding guard: only answer requests addressed by IP, localhost, this machine's name (also .local/.lan/.home/.home.arpa, Tailscale MagicDNS) or `allowedHosts`. Host names are matched against a strict DNS regexp because the Host may later be pasted into install scripts. Peers must be loopback, RFC 1918, link-local, Tailscale CGNAT (100.64/10) or IPv6 ULA/link-local; anything else (router port forward, UPnP, public IPv6) is refused even if a firewall lets it in. Browsers send Origin on cross-site state-changing requests (even to 127.0.0.1); agents and the TUI send none, so a mismatching Origin is refused. A URL's host drops the scheme's default port, as JS's URL does. Responses carry a CSP forbidding everything since the hub serves no HTML. Secret comparison is constant-time and an empty secret never matches.

**Where:** `security.go`

### Hub identity proofs (hubProof / ConnProof)

**Context.** Before sending the key, a client must know it is talking to the real hub.
**Decision.** `/api/info` without the key proves only knowledge of the key: `hex(HMAC-SHA256(key, "device-monitor-hub:"+nonce))` (upstream's). Because a squatter on the hub's port can relay that, `ConnProof` also covers both ends of the TCP connection as the hub sees them (client addr:port and hub's own): a relay's connection differs, and covering the hub end defeats a socket sharing the client's port (Windows SO_REUSEADDR). `machine-monitor pair` checks it per connection before sending the key. It only works where nothing rewrites addresses (loopback); other clients use hubProof.

**Where:** `handlers.go`, `security.go`, `hub_test.go`

### Pairing
**Decision.** One code at a time; it dies after PairTTL (upstream's 10 min) or `pairMaxWrong` (100) wrong guesses from everyone, capping guess odds at 1 in 10,000 whatever addresses a peer has. Each source gets PairTries (5) guesses (upstream counted them for everyone, so one peer could burn every code). Codes have ids carried by "paired"/"pairEnded" events so the shower knows which code was used/replaced. `{"replace": false}` (sent by `machine-monitor pair`) means "only if none active" (409 otherwise) so two runs can't hand out two codes of which one works; without it a new code replaces the old, as upstream. Pair and the TUI name themselves with a random owner on both their stream and code request; PairGrace after the owner's last stream ends the code, so a killed process (SIGKILL, crash) doesn't leave a code nobody shows (skeptic N3). A reconnect within the grace keeps the code. A code for an owner with no open stream isn't issued. Non-digits in the guess are ignored; the compare is constant-time; the registry-full check precedes counting so a refused attempt isn't a guess. Lock order: never hold the pair lock while waiting on `h.mu`. Exactly-at-deadline still works (upstream's `now > expires`).

**Where:** `pair.go`, `pair_test.go`

### Installers (install.sh / install.ps1)

**Context.** `GET /install.sh|ps1` serves a script that downloads the hub's own release and installs and pairs an agent.
**Decision.** Key required (as upstream); a refusal is itself a script that prints why and exits 1, so `| sh`/`| iex` fail loudly (the documented one-liner uses `--fail-with-body`; curl older than 7.76 uses a download-first form). The hub pins SHA-256s it verified itself: it fetches the release's checksums.txt once and checks its Sigstore signature before serving; a "dev" build can't serve installers. Values are substituted in one pass (never re-scanned for placeholders) and quoted for a single-quoted string (shQuote; psQuote also doubles typographic quotes, which PowerShell treats as quote ends). The Host header is pasted into a script only if it is a name/IPv4/bracketed IPv6 with `%25zone` (RFC 6874) and a valid port. `X-Forwarded-Proto: https` is honoured only from a trusted proxy. Each script wraps all work in a function/`main` called on the last line so a cut-off download runs nothing. install.sh: hashes without pipelines so a failed hash is not an empty one; copies next to the target then renames (atomic swap of a running binary); on any failure after install rolls back, restoring replaced binary/client.json (symlinks recreated as links via `cp -P`, dangling links untouched) and removing what it added; detects Apple silicon under Rosetta (uname says x86_64) and installs native; the key goes to `connect` on stdin so it never shows in `ps` (pipeline status is connect's). install.ps1: forces TLS 1.2 (5.1 may default to TLS 1.0, GitHub refuses it); a running .exe can be renamed but not overwritten so the old one is moved aside; leftover `.old` may stay locked.

**Where:** `install.go`, `install_test.go`

### Alert and settings refusals
**Decision.** Alerts package errors are worded without the values given (never a webhook URL), so the hub passes them to clients verbatim.

**Where:** `energy.go`

### Energy numbers
**Decision.** Bounds are 2–800 ascending finite ms timestamps over ≤32 days; ms→ns (×1e6) stays inside int64 (~9.22e18). `msTime` converts whole ms and the fraction separately since ms*1e6 in float64 loses the last ms near the limit. `round1` reproduces JS `+v.toFixed(1)`: the exact binary value rounded half up (0.15 is 0.1499… → 0.1, 0.25 → 0.3), sign applied afterwards, values beyond int64 tenths have no fraction left, and -0 is normalised since JSON would print it (test B15).

**Where:** `energy.go`, `energy_test.go`

### SSE streaming: modes, backpressure, resync

**Context.** At 250 devices the upstream snapshot is ~20 MB, so over a slow link it never finished before the stream was dropped (skeptic B1); Linux's kernel send queue holds megabytes, so batches queued for minutes and the TUI showed data minutes old (N1).
**Decision.** Two modes share event names/shapes. Upstream mode (default): snapshot with each device's last LiveHistory samples, then events; a client falling `streamBuffer` events behind is dropped (it reconnects for a fresh snapshot: dropping beats blocking every report). Compact mode (`?compact=1` or `X-Machine-Monitor-Stream: compact`, echoed back): snapshot without history (fetched from /api/history), events batched at most every `compactFlush`; reports, status and order coalesce per client so memory is bounded by device count and a slow link gets the newest state. A device's report keeps the slot of its first waiting report (merging newer ones, keeping up to `compactSamples` samples) so event order is preserved (report before the actionResult it carried; removal before a report that brings a device back). Status/order are whole-hub maps: newest only, sent last. If non-coalescable events exceed `compactBacklog`, a fresh snapshot replaces what it covers and the newest `compactKeep` alerts/action results/pairings plus newest alert/energy settings are kept and sent after it. A merged report still carries the newest state for clients that don't know `samples`; "lean" batches drop samples when the link is slower than the stream. Compact streams hijack the connection, write chunked gzip, and bound the kernel send queue (TCP_NOTSENT_LOWAT on Unix, a ~3 s send buffer on Windows, which also caps bytes in flight); the response head is written manually, the server read deadline cleared since net/http no longer watches it (so client departure is noticed), and `ch` of an upstream-mode stream is never closed so a handler can't drain a stale queue. Stream slots are held until the handler releases them so one stuck in a write still counts against MaxStreams. Writes use a fresh wall-clock deadline (time.Now, not the injected clock; `StreamWriteTimeout`) so a client that stops reading can't pin a handler. The stream registers before the snapshot is built so no event in between is lost; gzip is finished before the connection closes so the client sees a clean end, not "unexpected EOF". Streams that name a pair owner extend/end pair codes (see Pairing). Note: the original header mentions "paired once pairing lands"; pairing has since landed.
**Consequences.** Reverting to plain net/http writes or unbounded queues reintroduces B1/N1.

**Where:** `stream.go`, `sendq_unix.go`, `sendq_windows.go`, `hub_test.go`, `stream_test.go`

### Test harness constraints
- Test requests carry a timeout so a handler that streams instead of answering fails rather than hangs (hub_test.go).
- Cleanups run last-in first-out; closing a test stream after its body closes avoids Close waiting on it (pair_test.go, stream_test.go, commands_test.go).
- A timer test sleeps past the first timer so only a re-armed one can fire (hub_test.go).
- install_test.go: a version-manager shim for PowerShell may be unconfigured; :416: real install.ps1 run is skipped on Windows, where it would install a real agent and edit the user's PATH; :454: `irm` throws on a refusal so `iex` never runs.
- stream_test.go: the hijacked response carries a Date header as net/http's does.

### Hub: shutdown, offline detection, save backoff

**Context:** Registry saves are delayed by a timer and the hub must flag devices offline promptly.

**Decision:** Close stops the pending save timer; if it stopped before firing, the WaitGroup count is released by hand and the registry saved synchronously. checkOnline sends a "status" event the moment a device crosses OfflineAfter rather than waiting for the heartbeat, rechecking at most one second later because a new device may report in the meantime. A failing devices.json write is logged once, then retried with doubling backoff, and a recovery is logged once.

**Consequences:** Dropping the manual Done deadlocks Close; dropping the timer check delays offline display up to StatusInterval; logging every failure spams read-only data dirs.

**Where:** `internal/hub/hub.go`, `internal/hub/registry.go`, `internal/hub/hub_test.go`

### Device cap and per-device ingest ordering

**Context:** Untrusted agents can register arbitrary ids.

**Decision:** MaxDevices bounds the registry. deviceLock refuses (nil) to create a lock for a new id when full; pairing refuses with a clear sentence rather than pair a device that could never report. Reports for one device are serialised by its ingest lock so LastSeen never goes backwards and history and events stay in time order; handleRemove drops the lock.

**Consequences:** Removing the nil check lets floods grow memory; removing the lock reorders reports.

**Where:** `internal/hub/registry.go`, `internal/hub/pair.go`, `internal/hub/pair_test.go`, `internal/hub/hub_test.go`

### Pairing codes

**Context:** `machine-monitor pair` and the TUI both request codes.

**Decision:** A code request with `replace:false` fails with 409 if one is active so two runs cannot hand out two codes of which one works; an owner stream ties the code to the caller; DELETE /api/pair/code?id=N ends only the caller's own code so the next run need not wait; upstream-style requests replace the old code and the first holder is told via pairEnded.

**Consequences:** Keep id check on cancel, or one client can kill another's code.

**Where:** `internal/hub/pair.go`, `internal/hub/pair_test.go`

### Compact event stream (coalesce, resync, hijack)

**Context:** Slow clients (TUI over a slow link) cannot be allowed unbounded queues, and dropping them loses state. Upstream stream must stay unchanged.

**Decision:** The compact stream is opt-in via `?compact=1` or the Compact header (echoed on the response), gzip, and its snapshot carries the latest report but no history. Reports coalesce per device (newest state plus the newest compactSamples samples) in their first slot so ordering with action results is kept; a removal drops the waiting report. When non-coalescable events pile past compactBacklog, a fresh snapshot replaces them and a kept set (newest settings of each kind, newest compactKeep alerts, action results and pairings) follows it. The stream is hijacked from net/http and writes its own chunked body. The upstream stream stays unchanged and is dropped after streamBuffer events.

**Consequences:** Changing coalescing or keep rules loses alerts or reorders events for slow clients.

**Where:** `internal/hub/stream.go`, `internal/hub/stream_test.go`, `internal/tui/spark_seed_test.go`, `internal/tui/devices.go`

### Hub security: proxies, hosts, key transport, links

**Context:** The hub is reachable by LAN and Tailscale.

**Decision:** Trusted proxies are only addresses or CIDRs listed in config.json "trustedProxies" (none by default). The hub key is accepted as `Authorization: Bearer` or the dm_key cookie, as upstream. The MagicDNS name is an extra allowed Host name. Alert notification links prefer the tailscale serve HTTPS address (works away from home), else the first real LAN address.

**Consequences:** Defaults must stay closed; changing key transport breaks upstream agents.

**Where:** `internal/hub/install.go`, `internal/hub/security.go`, `internal/hub/remote.go`, `internal/hub/remote_test.go`, `internal/hub/handlers.go`

### Installer rollback

**Context:** One-line installers run on user machines.

**Decision:** A failure after the binary is installed rolls back: a fresh install leaves no binary or client.json, a replaced binary is restored, symlinks are restored as symlinks, and a dangling link is not deleted.

**Consequences:** Simplifying to remove/overwrite would destroy user files.

**Where:** `internal/hub/install_test.go`

### Config edge cases in hub

**Decision:** An overlapping time-of-use price already in config.json keeps its flat rate, logs once and does not wipe the price. A second hub on a data directory in use is refused with a sentence and may start once the first closes.

**Where:** `internal/hub/hub_test.go`

### Constants that must match upstream

**Context:** Upstream agents and clients interoperate with this hub.

**Decision:** CommandTTL (queued power action wait and agent acceptance), hub limits and timings, Tailscale status timings, ProcsWatch, AI check cadence (every 5th sample), request timeout (1.5 s), 8-group cap and the 2 s DefaultInterval match upstream values.

**Consequences:** Changing them breaks interop or signed-command expiry.

**Where:** `internal/hub/commands.go`, `internal/hub/hub.go`, `internal/hub/remote.go`, `internal/hub/procs.go`, `internal/collect/ai/ai.go`, `internal/collect/ai/sources.go`, `internal/tui/tui.go`
